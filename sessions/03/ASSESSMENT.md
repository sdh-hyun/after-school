# 3회차 실기평가 — Unity 객체 연결과 디버깅

## 평가 목적

완성된 코드를 복사했는지가 아니라 Unity의 객체, Component, Inspector 참조와 물리 조건을 이해하고 스스로 연결·수정할 수 있는지 확인한다.

## 평가 자료

- 실행 가능한 Unity 장면
- 개인 브랜치와 PR
- 디버깅 기록표
- 1분 이내 구두 설명
- 교사가 제시한 현장 변경 결과

## 수업 중 평가 시간

- 마지막에 몰아서 평가하지 않고 60~105분 실습·디버깅 중 순회하며 실시한다.
- 1인당 3분: 구두 설명 1분, 현장 변경·재실행 2분을 기준으로 한다.
- 기능이 아직 미완성인 학생도 현재 성공한 단계에서 설명과 조건 변경을 시킨다.

## 필수 기능

1. Player가 키 입력으로 이동한다.
2. Coin Trigger에 닿으면 `PlayerCollector`가 Coin을 찾는다.
3. 연결된 `ScoreManager.AddScore`를 호출해 점수를 올린다.
4. 획득한 Coin이 사라진다.
5. `CoinSpawner`가 Prefab을 생성한다.

## 구두 질문

학생마다 아래에서 2개를 선택한다.

1. GameObject와 Component의 차이를 현재 장면의 예로 설명하라.
2. `PlayerMover.cs` 파일만 만들고 Player에 붙이지 않으면 왜 움직이지 않는가?
3. `Awake`, `Start`, `Update`는 각각 언제 사용했는가?
4. `PlayerCollector`는 어떤 객체를 Inspector로 참조하고, 왜 필요한가?
5. `OnTriggerEnter2D`가 호출되기 위한 장면 조건을 설명하라.
6. Coin Prefab과 실행 중 만들어진 Coin 인스턴스의 차이는 무엇인가?
7. `NullReferenceException`이 발생했다면 가장 먼저 어디를 확인하겠는가?
8. 이동과 점수 코드를 한 Component에 모두 넣지 않은 이유는 무엇인가?

## 현장 변경 요구

학생마다 하나를 지정하고 3분 안에 수정·실행하게 한다.

- 이동 속도를 현재 값의 절반으로 변경한다.
- Coin 점수를 10에서 25로 변경한다.
- Coin 생성 위치를 교사가 지정한 좌표로 변경한다.
- 대각선 이동이 직선보다 빨라지지 않게 하는 코드를 찾아 설명한다.
- 두 번째 Coin을 다른 위치에 생성한다.
- Coin의 Collider 설정을 일부러 망가뜨린 뒤 다시 복구한다.

## 디버깅 실기

교사는 학생에게 서로 다른 오류 2개가 포함된 장면을 준다. 정답을 맞히는 속도보다 아래 순서를 지키는지 관찰한다.

1. 보이는 증상을 재현한다.
2. Console, Hierarchy, Inspector 중 어디를 먼저 볼지 선택한다.
3. 원인 가설을 말한다.
4. 한 가지 설정 또는 코드만 바꾼다.
5. 다시 실행해 원인이 맞았는지 확인한다.

### 사용할 오류 목록

| 오류 | 대표 증상 | 확인 위치 |
|---|---|---|
| `PlayerMover` 비활성화 | 입력해도 움직이지 않음 | Player Inspector |
| `speed = 0` | 입력해도 위치가 변하지 않음 | PlayerMover 필드 |
| Rigidbody2D 누락 | Trigger가 호출되지 않음 | Player Component 목록 |
| Coin `Is Trigger` 해제 | 충돌해도 획득되지 않음 | Coin Collider2D |
| ScoreManager 참조 누락 | Coin 충돌 시 NullReference | Console, PlayerCollector |
| Prefab 참조 누락 | 시작할 때 NullReference | Console, CoinSpawner |
| Coin Component 누락 | 충돌하지만 바로 return | Coin Prefab Inspector |

## AI 사용 확인

- AI 사용 자체는 감점하지 않는다.
- AI가 만든 코드 또는 설명을 사용했다면 해당 부분을 가리키게 한다.
- 변수명, 메서드 호출 순서, Inspector 연결을 자기 말로 설명하게 한다.
- 현장 변경을 직접 완료하지 못하거나 설명하지 못하면 해당 기능은 완료로 인정하지 않는다.
