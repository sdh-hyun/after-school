# 1회차 진단평가 — Git 작업과 설명

이 평가는 첫날 선발을 확정하는 시험이 아니라, 2~4회차 지도 수준과 지원이 필요한 학생을 파악하기 위한 진단이다.

## 평가 자료

- 학생 PR URL
- 브랜치명과 commit 메시지
- 실습 중 관찰 기록
- 30~60초 구두 설명
- 종료 티켓

## 채점 기준(100점)

| 항목 | 배점 | 확인 내용 |
|---|---:|---|
| 기능 완성 | 40 | clone 5, 개인 branch 10, README 수정·commit 10, push 5, PR 10 |
| 개념·작업 설명 | 25 | commit/push 차이 10, branch 이유 8, PR 목적 7 |
| 디버깅·개선 | 20 | 현재 상태 확인 5, 오류 메시지 활용 5, 피드백 반영 5, 현장 조건 변경 5 |
| 제출·협업 태도 | 15 | 브랜치 규칙 5, PR 내용 5, 개인정보·AI 사용 공개 5 |

미완성이라도 오류를 정확히 읽고 도움을 받은 뒤 스스로 재시도하면 디버깅·개선 점수를 부여한다.

## 구두 질문 목록

학생마다 두 개를 선택한다.

1. 파일 저장과 commit의 차이는 무엇인가?
2. commit과 push의 차이는 무엇인가?
3. branch를 사용하는 이유는 무엇인가?
4. PR을 만드는 목적은 무엇인가?
5. 지금 내 브랜치와 원격 반영 여부를 어떻게 확인할 수 있는가?
6. 두 사람이 같은 줄을 다르게 수정하면 Git이 왜 자동으로 고르기 어려운가?

## 현장 변경 요구

PR 제출 후 아래 중 하나를 시킨다. 3분 이내에 스스로 방향을 잡는지를 본다.

- commit 전에 README 문장 한 줄을 교사가 지정한 표현으로 바꾸기
- 이미 commit한 학생은 README 오탈자를 고쳐 두 번째 commit 만들기
- PR 제목 또는 본문의 빠진 항목 보완하기
- 현재 branch 이름과 base branch를 직접 찾아 보여 주기

## AI 사용 확인

- AI 사용 여부 자체는 감점하지 않는다.
- AI를 사용한 부분을 가리키고 자신의 말로 설명하게 한다.
- 교사가 조건 하나를 바꾸었을 때 직접 수정할 수 있는지 확인한다.
- 설명 또는 수정이 불가능하면 해당 완료 항목을 인정하지 않는다.

### 빠른 분류 표기

- A: 혼자 완료하고 이유를 설명함
- B: 약간의 안내 후 완료하고 설명함
- C: 단계별 지원이 필요하지만 피드백을 반영함
- D: 환경 문제 또는 기초 지원이 필요함
- 별도 기록: 반복 미제출, 설명 불가, 협업 규칙 위반
