# 1회차 학생 안내 — 내 첫 Pull Request

## 오늘 할 일

오늘은 코드를 많이 만드는 날이 아니라, 앞으로 팀 프로젝트에서 작업을 안전하게 합치는 기본 절차를 익히는 날입니다.

오늘의 필수 흐름:

```text
clone → branch → 파일 수정 → commit → push → Pull Request
```

## 협업 규칙

1. `main` 브랜치에 직접 push하지 않습니다.
2. 내 작업은 별도 브랜치에서 진행합니다.
3. 다른 사람이 변경 내용을 볼 수 있도록 PR을 만듭니다.
4. AI 사용은 허용되지만 사용 여부를 밝힙니다.
5. 제출한 내용은 본인이 설명하고, 조건이 바뀌면 직접 수정할 수 있어야 합니다.
6. 저장소에 실명, 이메일, 비밀번호, 토큰 등 개인정보와 비밀정보를 올리지 않습니다.

## 실습

### 1. 저장소 가져오기

- 교사가 제공한 GitHub 저장소 URL을 Fork에서 clone합니다.
- 저장 위치를 기억하고, 다른 저장소를 열지 않았는지 이름을 확인합니다.

### 2. 개인 브랜치 만들기

- 브랜치명: `diagnostic/<GitHub아이디>`
- 현재 브랜치가 새 브랜치인지 확인한 뒤 수정합니다.

### 3. README 수정하기

교사가 지정한 학생 실습 구역에 다음을 추가합니다.

```text
- 표시 이름/번호:
- 만들고 싶은 게임 기능:
- Git 경험: 처음 / 조금 / 사용해 봄
- 오늘 이해한 Git 용어와 설명:
```

실명 대신 교사가 배정한 번호나 GitHub 아이디를 사용해도 됩니다.

### 4. commit하기

- 변경 파일이 README 하나인지 확인합니다.
- 메시지: `docs: add <아이디> diagnostic`
- commit은 내 PC의 Git 기록에 변경 시점을 남기는 작업입니다.

### 5. push하고 PR 만들기

- 내 브랜치를 원격 저장소로 push합니다.
- GitHub에서 `main`으로 보내는 Pull Request를 만듭니다.
- PR 제목: `[진단] <아이디> Git 실습`
- PR 본문:

```text
## 변경 내용
-

## 직접 확인한 것
-

## AI 사용 여부
- 사용 안 함 / 사용함: 사용한 부분 설명
```

### 6. 제출 확인

- [ ] 브랜치가 `diagnostic/<아이디>`이다.
- [ ] 변경 파일이 의도한 파일뿐이다.
- [ ] commit 메시지가 작업 내용을 설명한다.
- [ ] PR 대상(base)이 `main`이다.
- [ ] PR URL을 교사에게 제출했다.

## 막혔을 때 먼저 확인할 것

- 수정 내용이 안 보임: 지금 연 폴더와 브랜치가 맞는가?
- GitHub에 commit이 안 보임: push했는가?
- PR 버튼이 안 보임: 원격에 내 브랜치가 있는가?
- 수정하면 안 되는 파일까지 보임: commit하기 전에 교사에게 확인한다.

3. 다음 수업에서 C# 코드로 직접 바꿔 보고 싶은 조건 한 가지를 적으세요.
